WinRM

WinRM（Windows 远程管理）是 Microsoft 实现的 WS-Management 协议，基于SOAP 的防火墙友好协议，用于系统管理和信息交换。它允许 IT 专业人员和开发人员远程管理 Windows 服务器，获取管理数据，执行自动化脚本。经常用来命令执行关闭防火墙
netsh advfirewall set allprofiles state off

WinRM 默认使用 5985 端口（HTTP）和 5986 端口（HTTPS）进行通信，需要配置WinRM 侦听器和 TrustedHosts 才能从远程计算机获取数据。WinRM 服务在 Windows Server2008 R2 之后默认开启，家庭版的 Windows 默认关闭。

好处是客户端无感，不占用连接数。一定程度上规避安全设备。支持不同类型的身份认证，如 NTLM 和 Kerberos 协议。所以拿到ST后、有了票据可以直接Winrm。
Winrs error:句柄无效->CS工具问题换vshell
powershell 中使用Enable-PSRemoting命令开启服务，实际环境中一般依靠端口 5985 和 5986 来判断服务是否开启。

域内用户枚举与密码喷洒

前提：拿不到域内机器但是能通信
前期在学习 kerberos 协议时，我们发现 AS-REQ 数据包中会包含用户名和 hash 值，那么就可以通过 kerberos 的响应包来判断进行认证时提供的用户名和 hash 值是否正确，微软官方也给出了参考。
Kerberos 身份验证故障排除指南 - Windows Server | Microsoft Learn
4771(F) Kerberos pre-authentication failed. - Windows 10 | Microsoft Learn
看报错来枚举

工具

kerbrute
获取域控IP
域内用户枚举：
shell kerbrute_windows_amd64.exe userenum -d deyu.com –dc 192.168.197.10 username.txt
爆破域管理员 administrator:
shell kerbrute_windows_amd64.exe bruteuser –dc 192.168.197.10 -d deyu.com password.txt administrator
任意方式上线，这里直接建立 ipc 连接配合 jump exec
shell net use \192.168.197.10\ipc$ “admin..@123” /user:gouzi\administrator
jump psexec 192.168.197.10 1

AS-REP Roasting 攻击

该攻击发生在 AS-REP 数据包，如果管理员在域控上勾选了”不要求 kerberos 预身份验证”，就可以对用户账号进行离线爆破。这一不安全的配置会导致我们使用某个用户进行预认证的时候，不需要提供密码就能返回 TGT，在这个 TGT 中又存在 enc-part，即使用用户 hash 加密的数据，那么可以尝试对这个加密数据进行解密或者暴力破解，拿到该用户的明文密码。
原理：AD目录下如果该用户的属性的账户账户选项选择了不要求kerberos预身份验证

抓取 enc-part
使用 ASREPRoast.ps1 进行攻击并且抓包。
因为要域用户身份和 LDAP 协议向域控查询,所以要以域用户 shell 运行该脚本 不然可能会失败 这个工具抓出来的 enc-part 可能不对，需要多抓几次。
还可以使用 Rubeus,但是这个工具使用 c#写的，需要.NET 环境，不是很方便，出于这个工具的强大可以自行了解。
该脚本自动寻找存在错误配置的用户信息 直接运行即可

使用hashcat读取
根据 enc-part 的值破解出用户 hash，推荐工具 hashcat：
hashcat -m 18200 encpart.txt pass.txt –force
18200 就是这个工具专门用来破解 AS-REP 数据包中 enc-part 的指定格式，
更多格式使用-h 查看
官网地址:https://hashcat.net/wiki/doku.php?id=example_hashes
