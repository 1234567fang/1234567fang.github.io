kerberos协议攻防：黄金白银票据和委派攻击

发表于2024-12-30|更新于2025-03-16
|阅读量:

Kerbors协议详解

  1. AS_REQ: Client 向 KDC 发起 ASREQ,请求凭据是 Client hash 加密的时间戳(预认证)
    由于在进行认证的时候，是用用户 hash 加密时间戳，即使在使用密码进行登录的情况下，也是先把密码加密成 hash，再进行认证。因此在只有用户hash，没有明文密码的情况下也是可以进行认证的。
    域内用户枚举：可以使用不同的用户让 KDC 去 AD 中查询是否存在，比对响应包差异(AS-REP)判断用户是否存在。
  2. AS_REP: KDC 使用 Client hash 进行解密，如果结果正确就返回用 krbtgt hash 加密的 TGT 票据，TGT 里面包含 PAC,PAC 包含 Client 的 sid，Client所在的组。
    黄金票据伪造:krbtgt 用户的 hash 值。只需要知道 krbtgt 用户的 hash 值，就能伪造任意 TGT。
    只校验TGT，因为krbtgt相当于最高权限，hash就没必要了
    Roasting:由于管理员错误配置（不要求 Kerberos 预身份验证）,导致可以离线爆破密码。
  3. TGS-REQ: Client 凭借 TGT 票据向 KDC 发起针对特定服务的 TGSREQ 请求
    由用户密码解出CT_SK，再用来加密并发送
  4. TGS_REP: KDC 使用 krbtgt hash 进行解密，如果结果正确，就返回用服务hash 加密的TGS 票据(这一步不管用户有没有访问服务的权限，只要 TGT正确，就返回 TGS 票据)
    白银票据:只需要知道 server 机器用户的 hash，就可以伪造一张特定服务的ST。保证服务的正确性：只有服务器知道serverhash
    kerberosRosting 攻击:允许攻击者请求并获取具有已注册服务主体名称（SPN）的服务的服务票证（ST），然后尝试破解这些票证以获取服务帐户的密码。
    客户端收到 ST 之后，使用 CT_SK 解密数据包，再使用 CS_SK 加密数据包。

    服务端收到客户端发送的 ST 之后，会进行验证:
    • 使用本机机器用户的 hash 解密 ST 得到 CS_SK(通过白银票据可伪造)
    • 使用 CS_SK 解密 ST 中的第一部分，得到相关信息
    • 对比成功后建立信任关系
  5. AP_REQ: Client 拿着 TGS 票据去请求服务
  6. AP_REP: 服务使用自己的 hash 解密 TGS 票据。如果解密正确，就拿着 PAC（校验用户是否有权限访问)

黄金票据

假设我们已经控制了 DC，能够通过各种手段获取 krbtgt 用户的 hash 值，就能够不依靠 KDC 凭空生成一张黄金票据，这种做法比较隐蔽且不好溯源。所以一般用来作为内网权限维持（黄金票据可以在工作组环境下使用）的一种常用手段。访问域内任何用户，可离线生成，伪造KRBTGT账户的NTLM哈希生成TGT票据，获取域管理员权限。关键在于破解域控制器的AES256加密密钥。
利用条件
• krbtgt 用户的 hash 值
• 域名
• 域的 SID 值
• 伪造用户

域的 sid 值使用任意域用户执行 whoami /all 即可得出。最后四位不用输入
1、使用 mimikatz 制作黄金票据并且注入内存

然后做横向移动：jump psexec xxx.deyu.com 1

2、使用 impacket-ticketer：该工具生成.ccache 票据。

直接上线
利用工作组机器使用黄金票据访问 dc,如果当前机器不能通过域名直接访问机器，就需要修改 host文件或者 dns 配置。比如：

echo 192.168.121.77 xxx.deyu.com >> C:

netsh interface ipv4 add dns 本地连接 192.168.121.77

这里的本地连接是网卡名字，可以使用 systeminfo 看见，中文机器常使用”本地连接”

流量检测方法：

  • 票据请求（AS-REQ）中encrypted-timestamp字段时间戳异常
  • TGS-REP响应中PAC（特权属性证书）的签名算法与域策略不符。

白银票据

白银票据就是伪造 ST 票据，在整个 kerberos 协议认证过程中，跳过了 TGS 的认证。一般伪造 ST 票据中的服务都是系统自带的服务，比如 CIFS、HOST 服务，方便后续横向移动。
前提条件
• 域名&域 SID
• 服务端全域名
• 服务端可利用的 SPN
• 服务端 SPN 注册用户的 hash 值(一般选择机器用户 hash)
• 需要伪造的用户名

servername的hash->SPN 注册用户的 hash
机器用户 hash 值( SPN 注册用户的 hash 值)的获取方式：
hashdump(本地用户)
• mimikatz-域管理员 dcsync
• secretsdump-域管理员读取密码
rc4后填WIN-HTPPB3UEPF6$的ntml的hash
mimikatz kerberos::golden /domain:deyu.com /sid:S-1-5-21-2279029564-276648203-1281631128 /target:WIN-HTPPB3UEPF6.deyu.com /service:cifs /rc4:d85668422c9be8e9642fd903b3b175a2 /user:Administrator /ptt

钻石票据

在后渗透当中，咱拥有域控一定的权限之后就可以转储ntds.dit并获取krbtgt密钥。而黄金票据和白银票据的问题在于它们很容易被发现。一旦 KDC服务收到TGT/ST，并且在SIEM中收到日志，就很容易被现在的安全设备所检测出来。

钻石门票是以更隐秘的方式获取类似门票的替代方案，当获取到TGT中的krbtgt密钥与服务账户密钥，可以请求合法票据、解密 PAC、修改它、重新计算签名并加密再次取票。 该技术可以生成与合法 PAC 高度相似的 PAC，并且还可以生成合法请求

  • 攻击者首先获取一个合法的TGT，通常通过正常认证流程或利用漏洞。
  • 使用域的krbtgt账户哈希解密TGT。krbtgt账户是Kerberos信任的关键，哈希泄露通常通过DCSync攻击或密码哈希转储获得。
  • 修改TGT的字段，例如更改用户身份、权限组或票据有效期。
  • 使用krbtgt哈希重新加密修改后的TGT，使其看起来合法。
  • 最终，攻击者可以使用此伪造的TGT请求服务票据，访问域中的任何资源。

[!NOTE]
PAC 是一种传递域控制器 (DC)提供的授权相关信息的结构。身份验证协议使用 PAC 来验证身份以传输授权信息，从而控制对资源的访问。完成身份验证后，下一个任务是决定是否授权特定请求。而 DC 包括 PAC 中的授权数据，例如安全标识符 (SID)和相对标识符 (RID)

黄金票据攻击和钻石票据攻击都需要访问krbtgt密钥。然而，钻石票据攻击需要访问AES256密钥，黄金票证攻击需要利用伪造票证授予票证 (TGT) 钻石票证攻击则利用了域控制器 (DC) 请求的真实 TGT 进行解密和重新加密进行票据攻击。钻石票据更注重修改现有合法TGT，直接修改TGT的PAC实现伪造，而不是完全从头创建。这种技术在检测上更加隐蔽，因为TGT本身是基于真实请求的，但修改的字段可能触发异常检测。

蓝宝石票据

蓝宝石票据是更先进的TGT伪造技术，基于请求后获得的合法门票。涉及Kerberos协议的S4U2self和用户到用户（U2U）扩展。蓝宝石票据攻击可以创建一个模拟任何用户的 TGT，结合 S4U2Self + U2U 组装真正的 TGT 和真正的 PAC。该 PAC 会替换合法票据中的 PAC

  • 攻击者首先获取一个普通用户的凭据（如Joe），通过KRB_AS_REQ获取其TGT。
  • 使用U2U和S4U2self技巧，请求一个服务票据，指定服务名称（sname）为Joe的用户名，但使用高权限用户（如域管理员）的身份（通过PA_FOR_USER结构）。
  • 此服务票据包含高权限用户的PAC，攻击者使用Joe的凭据解密，获取此PAC。
  • 然后，攻击者解密Joe的TGT（使用krbtgt哈希），替换其中的PAC为高权限用户的PAC，并修改TGT的客户端名称（cname）以匹配被冒充的用户。
  • 重新加密TGT后，攻击者即可使用此伪造的TGT冒充高权限用户。

蓝宝石票据的隐蔽性更高，因为其PAC是合法获取的，与AD记录完全匹配，难以通过传统PAC验证检测。

[!NOTE]
Microsoft 实施了 Kerberos 扩展以避免将用户的 TGT 保留在内存中。该扩展称为S4U（Service for User），它由S4U2Self和S4U2Proxy组成。S4U2Self 允许服务代表任何用户向其自身请求票证。S4U2Proxy 将允许一个服务向另一个服务进行身份验证。

U2U Authentication
允许客户端请求使用 TGT 中的会话密钥对 KDC 颁发的票证进行加密，该会话密钥来自颁发给验证身份验证方的 TGT。

U2U + S4U2Self(不使用S4U2Proxy)
允许没有 SPN 的用户使用 S4U2Self 扩展。在此交换中收到的服务票证使用服务器的密钥进行加密（在这种特定情况下，服务器可以是没有 SPN 的用户），因此，可以使用服务器的密钥来解密目标用户的 PAC。KRB_TGS_REQ 数据包将具有这两种方法的所有功能。

TGT&ST

tgt::ask /user:域用户 /domain:域名 /password:密码

tgt::ask /user:administrator /domain:gouzi.com /password:admin..@123$%

区别

黄金票据与白银票据的区别：
可转换
黄金是全部服务
白银是某些服务（servername的限制）

钻石票据与蓝宝石票据的区别：
在钻石票据攻击当中，修改是通过添加额外权限或完全修改所请求的 TGT 的原始 PAC。而在蓝宝石票据当中，则是使用 Kerberos 委派获取高权限用户的合法 PAC 来修改 TGT，并将其替换为原始票证的 PAC。
