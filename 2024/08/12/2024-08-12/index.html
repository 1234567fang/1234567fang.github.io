git泄露

使用direarch发现.git目录时可能存在泄露
默认：githacker –url http://127.0.0.1/.git/ –output-folder result
暴力破解：githacker –brute –url http://127.0.0.1/.git/ –output-folder result
生成git泄露文件
查看历史版本日志 git log
版本回退 git reset –hard xxx(版本编号)

JS接口

对js.map反编译
app.js
secretkey accesskey是云主机账户密码，使用云资产监测工具

使用reverse-sourcemap -v xxx.js.map -o 目录名

推测存在未授权的具体情况：
1、数据的某些应该有的功能点，而页面未展示
例如数据的增删改查，少了某一项
2、没有突破点的页面
例如无法登录的平台，或者进了后台无法使用，再比如空白页面等
3、没有权限的某个功能
某个功能需要更高权限或等级，有可能只是前端限制，完全可以尝试拼接去寻找突破口
方法一：js检索
方法二：相关参数或全局接口参数Fuzz
用findsomething在js里找分包 右键js复制链接地址
通过功能猜测接口 然后推测隐藏功能和接口，猜关键词info带上参数（json多余参数不报错）

path
:id 1 给占位符一个值
Path结尾为/ 可能后面还有路径
网址带# 也要带上测试

经验：
405可以试试改POST请求 构造参数
content-type /json
{}（置空）
改状态码 改token 可能用户后台界面通用（学校）
将正常密文保存成正常包
将异常行为的返回包改成上面的正常包（银行）
