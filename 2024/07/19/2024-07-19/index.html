cd \ 根目录

cls 清屏
md 文件名 或 mkdir 文件名 创建文件夹
rd 或 rmdir（rd /s /q 盘符:\路径\） 删除文件
type nul>文件名.后缀名 创建文件（在目录中）

ren xxx xxx 重新命名
move 1.txt d:/ 将文件移动到d盘
1.txt edit 打开1.txt文件
set 查看环境变量
hostname 主机名
runas /user:administrator cmd 切换管理员
CHCP 65001 修改字体编码为UTF-8
tracert 发送数据包途径的路径
默认密码目录：
  • windows\System32\config\SAM 存放 windows 账号密码的文件（重要）加密过的系统帐号的密码文件，一般软件是打不开的。
  • Windows\System32\config\SYSTEM 包含加密SAM数据库的密钥，需要与SAM文件一起使用才能解密密码哈希
  • windows\System32\drivers\etc\hosts 文件（重要）负责解析域名并优先于 DNS 服务，通常很多恶意软件会恶意更改该文件来达到劫持网站的目的。
  • Windows\System32\winevt\Logs 存储 Windows 系统事件日志文件

Docker

Docker 安全机制
为了提升容器的安全性，Docker 内置了多种安全机制：

命名空间隔离Namespace：通过 PID、网络和挂载命名空间实现资源隔离，确保容器之间、容器与宿主机之间的隔离。

控制组资源限制cgroups：对容器的 CPU、内存、磁盘 I/O 等资源使用进行精细化控制，防止某个容器耗尽宿主机的资源。

能力机制Capabilities：通过最小化权限分配来提升安全性，只为容器分配运行必要的权限。

安全配置文件seccomp：过滤容器内可以使用的系统调用，减少容器访问敏感内核接口的可能性。

容器逃逸

容器逃逸是指攻击者从一个原本应该被隔离的容器内部，突破安全边界，获取到宿主机操作系统权限或访问宿主机资源的行为。
1、配置不当
危险做法：赋予容器过多权限
docker run –privileged …
危险做法：将宿主机根目录挂载到容器
docker run -v /:/host …
2、内核漏洞
脏牛藏管
3、docker守护进程攻击
危险做法：将Docker socket挂载到容器
docker run -v /var/run/docker.sock:/var/run/docker.sock …
docker API暴露
4、Web应用存在RCE
